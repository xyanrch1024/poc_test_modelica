# Feature Specification: 支持 if 语句（条件方程与条件表达式）

**Feature Branch**: `003-if-statement-support`

**Created**: 2026-09-12

**Status**: Draft

**Input**: User description: "支持if语句"

## Clarifications

### Session 2026-09-12

- Q: 首期支持哪些 `if` 构造？ → A: 条件表达式（`y = if c then a else b`）与条件方程（`if c then eq; else eq; end if;`）两者都支持（Option A）。
- Q: 条件是否能依赖随时间变化的量（状态变量/代数量）？ → A: 允许；切换瞬间按输出步长边界离散求值，无事件精化（Option A）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 模型中按条件选择方程或表达式取值 (Priority: P1)

建模工程师在方程集中使用 `if` 构造表达分段/条件行为：根据某个条件（如温度阈值、
布尔开关）在不同分支中选择不同的方程或表达式取值，完成"转换 → 构建 → 运行"全流程，
得到与分支语义一致的确定性 CSV 轨迹。

**Why this priority**: 条件行为是建模中最常见的表达能力缺口（首期子集明确把 `if/h当` 列在
不支持清单）。没有它，分段函数、启停逻辑、阈值切换都无法表达，是子集扩围的核心主干。

**Independent Test**: 给定一个行为已知的分段模型，独立执行"转换 → 构建 → 运行 → 检查输出轨迹"
四步，全程无需人工修改生成物；在不触发条件的区间与触发条件的区间分别验证其分支语义正确。

**Acceptance Scenarios**:

1. **Given** 一份含条件表达式的模型（如 `y = if x > 0 then a else b`），**When** 用户发起转换，
   **Then** 系统产出一套可直接构建、运行的 C++ 代码，且输出轨迹在触发/不触发条件区间与预期一致。
2. **Given** 一份含条件方程的模型（如 `if on then der(x) = -k*x; else der(x) = 0; end if`），
   **When** 用户发起转换并运行，**Then** 输出轨迹符合分支语义，两个分支各自的方程均被正确执行。
3. **Given** 同一模型生成的程序，**When** 连续运行两次，**Then** 输出 CSV 逐字节一致（确定性，FR-007）。

---

### User Story 2 - 分支组合与嵌套表达 (Priority: P2)

模型使用 `elseif` 多分支与嵌套 `if` 表达更复杂的分段逻辑（如三段温度控制），
编译器能正确处理，不引入歧义或错误诊断。

**Why this priority**: 单一二分支是基础，多分支/嵌套是实际工程模型的常见形态；但作为第二优先级，
可在两分支主干稳定后再扩展，属于递增强化而非核心价值。

**Independent Test**: 提交含 `elseif` 与嵌套 `if` 的样例，验证分支选择正确且输出确定。

**Acceptance Scenarios**:

1. **Given** 含 `elseif` 链的模型，**When** 用户发起转换并运行，**Then** 各分支条件按声明顺序求值，
   且输出与预期分段行为一致。
2. **Given** 含嵌套 `if`（表达式内嵌 `if`，或条件方程内嵌套）的模型，**When** 用户发起转换，
   **Then** 系统正确解析并生成等价行为，产生确定性输出。

---

### User Story 3 - 非法 if 构造的清晰诊断 (Priority: P3)

当模型中存在不完整或不合法的 `if` 用法（缺少 `then/else/end if`、条件不是布尔表达式、
`if` 出现在非法位置等）时，编译器拒绝翻译并报告含文件名与行号的可读诊断。

**Why this priority**: 静默错译比失败更危险；诊断体验建立在分支主干可用之后排第三。

**Independent Test**: 提交各类非法 `if` 样例，逐条核对诊断包含文件名、行号与原因，且失败时不产生生成物。

**Acceptance Scenarios**:

1. **Given** 一份含语法错误 `if` 的文件（如缺 `then`），**When** 用户发起转换，
   **Then** 系统报告含文件名与行号的错误信息并以失败状态结束，不产出生成物。
2. **Given** 一份条件非布尔类型的文件，**When** 用户发起转换，
   **Then** 系统明确指出条件应为布尔类型及其位置。
3. **Given** 一个含多个错误的输入文件，**When** 用户发起转换，
   **Then** 系统尽可能一次性报告全部可发现的 `if` 相关问题，而非每次只报第一个。

---

### Edge Cases

- `if` 条件为常量真值或假值：必须按编译期常量折叠行为处理，且与运行时求值结果一致。
- 条件表达式 `if c then a else b` 缺少 `else` 分支：必须明确拒绝并说明缺失。
- 条件方程分支集合不一致（各分支方程数量/变量集合不同，导致方程数与未知量不匹配）：
  必须在转换阶段检出并给出诊断。
- 条件依赖代数环中的量（条件所在的代数子图构成环）：必须检出并明确报告，不得死循环。
- 嵌套过深（数千层 `if`）：转换必须在可接受时间与内存内完成或给出清晰失败，而非崩溃。
- 生成代码运行时条件切换（若允许时间依赖条件）：必须在切换点给出可复现、确定性的行为
  （按输出步长离散处理，步内不得出现未定义中间态）。
- `der()` 出现在 `if` 条件内部：必须拒绝并指出 `der` 仅允许出现在方程左侧。
- 含注释的多行 `if` 排版：与单行形式行为完全一致。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在方程右侧与代数表达式中支持条件表达式
  `if <布尔条件> then <表达式> else <表达式>`，且 `else` 分支 MUST 存在。
- **FR-002**: 系统 MUST 在方程节中支持条件方程
  `if <布尔条件> then <方程>; {elseif <布尔条件> then <方程>;} [else <方程>;] end if;`。
- **FR-003**: 系统 MUST 支持 `elseif` 多分支与 `if` 的嵌套（条件表达式内嵌套、条件方程内嵌套）。
- **FR-004**: `if` 条件 MUST 是布尔表达式（关系/逻辑运算结果或布尔变量）；
  非布尔类型 MUST 被拒绝并指出位置。
- **FR-005**: 所有 `if` 相关语法错误 MUST 产生包含文件名、行号与原因的诊断（FR-006 延续）；
  成功/失败退出状态 MUST 可区分。
- **FR-006**: 相同输入 MUST 每次产生完全相同的转换结果与运行轨迹（确定性，FR-007 延续）。
- **FR-007**: 生成代码中的标识符 MUST 与源模型保持可追溯对应（FR-008 延续）。
- **FR-008**: 方程数量与未知量匹配约束 MUST 在分支存在时按分支分别校验（即各分支各自可解），
  欠定/超定分支 MUST 被检出并说明。
- **FR-009**: 新增的每个受支持 `if` 构造（条件表达式、条件方程、`elseif`、嵌套）MUST 至少由一个
  自动化测试覆盖其"转换→运行"行为；每个已修复缺陷 MUST 附带回归测试。
- **FR-010**: `if` 条件 MUST 允许依赖运行期变量（状态变量/代数量）；条件每次输出步按布尔求值，
  切换在步边界生效，不得产生步内未定义中间态。此求值语义 MUST 随文档发布（FR-004 子集边界延续）。

### Key Entities *(include if feature involves data)*

- **条件表达式 (`IfExpr`)**: 布尔条件 + then 分支表达式 + else 分支表达式；出现在任意表达式位置，
  整体又是一个表达式（有确定类型）。
- **条件方程 (`IfEquation`)**: 一个或多个(条件 → 方程/方程块) 分支，外加可选的 else 分支；
  出现在方程节中，整体等价于一组按条件激活的方程。
- **布尔条件**: 由关系/逻辑运算或布尔变量构成，作用于分支选择；可依赖常量、参数或运行期变量。
- **分支校验**: 对每个条件方程，验证各分支的方程集合能解出相同未知量集合（平衡性）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ≥5 个覆盖全部受支持 `if` 构造的代表性模型完成"转换→构建→运行"闭环，
  全程零人工修改生成物，闭环成功率 100%。
- **SC-002**: 全部 `if` 特性用例的输出轨迹与解析/参考期望值在既定容差内一致率达到 100%
  （条件依赖常量/参数时与解析值逐点一致；允许时间依赖条件时按既定容差）。
- **SC-003**: 100% 的非法 `if` 输入被拒绝并返回含位置信息的诊断，零静默错译案例。
- **SC-004**: 引入 `if` 后，既有 20+ 用例的转换→运行→比对结果不回退（回归全绿）。

## Assumptions

- 首期 `if` 面向连续时间模型中"按条件选择代数方程/表达式"的静态分段语义；
  事件驱动的离散切换（如精确阻尼/过零点精化）不在首期范围，运行期条件切换按输出步长边界离散处理。
- 条件表达式要求 `else` 分支显式给出（Modelica 语义）；条件方程可不含 `else`（等价于空分支）。
- `if` 仅作用于方程与表达式层面；`algorithm` 节中的 `if` 语句依赖 `algorithm` 支持，不在首期范围。
- 不引入新的数值求解器能力（如事件检测）；依赖现有数值推进机制，分支切换不影响退出码语义。
- 嵌套深度受解析器实现约束，超深输入给出清晰失败而非崩溃。

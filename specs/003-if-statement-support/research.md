# research.md: 技术决策记录 — 支持 if 语句

**Date**: 2026-09-12 | **Branch**: `003-if-statement-support` | **Phase 0**

## 1. 研究问题

1. `if` 在 Modelica 语义中与"方程"系统的关系是什么？
2. 条件方程如何在**不引入事件系统**的前提下编译成现有"代数/微分直通"代码生成模型？
3. 与既有子集的交集点（der、白名单函数、配平、代数环检测）各有什么限制？
4. 本 POC 范围（明确不支持项）如何划定？

## 2. 事实依据

### 2.1 Modelica 规范（MLS 8.3.4）

- 条件方程：`if b then {eq;} {elseif b then {eq;}} [else {eq;}] end if;`，
  条件必须是**标量 Boolean 表达式**。
- **分支平衡规则**：切换条件非纯参数表达式的 if 方程，各分支（缺省 else 计 0 个方程）的
  **方程数必须相等**。理由（规范原文）："若违反，单赋值规则不成立——仿真中方程数可能变化而未知量数不变"。
- 某分支不选中则该分支各方程"对该次求值无影响"。
- 条件表达式形式在表达式中 `else` **必选**（`if e1 then e2 else e3`）。

### 2.2 本 POC 求解架构（001 设计）

- 平铺后 DAE 重组为：状态量 `der(x)=f1(x)` + 代数量 `y=f2(x,y)`（转发有序）。
- 生成 `compute_algebraic()`（逐代数量赋值）+ `deriv()`（逐状态求导）+ 固定步长 RK4 主循环。
- 全部是**直线赋值序列**；无求解器、无事件、无收敛循环。
- 既有配平/MC0301-0304 校验在 semantic 阶段闭式完成。

### 2.3 与事件系统的关系

- 完整 Modelica 中，运行期条件到达真值边沿会触发**事件**（含过零精化、再初始化）。
- Clarify Q2 已确认本 POC **不做事件**：条件在每次输出步开始按当前值布尔求值，
  切换在步边界生效，随后正常积分。→ 与规范兼容的"离散近似"，属既定子集边界而非缺陷。

## 3. 决策记录

### D1: 条件方程限定为"单方程单未知量"分支

- **内容**：允许的 if 方程语法为：
  ```
  if c1 then v = e1; elseif c2 then v = e2; ... else v = en; end if;
  ```
  每分支恰好一个等式；LHS 必须是同一未知量 `v`（`v` 可为 `der(x)` 形式）。
- **理由**：直接满足 2.1 的分支平衡约束（各分支 1 个方程），unknown 集恒定 → 单赋值规则成立；
  且可归约为三元表达式（见 D4），不增加 codegen 块结构。
- **边界**：多方程/不同未知量分支 → MC0305（将来扩展为块级 if，同时引入块级依赖分析）。

### D2: 归约后的依赖分析按"分支并集"建边

- 代数量 `v = f(c1,e1,...,en)` 依赖 `vars(e1) ∪ … ∪ vars(en) ∪ vars(条件)`；
  状态量 `der(x)` 同理。拓扑排序/代数环检测沿用 001 算法，仅把边集按并集扩充。
- **结论**：条件分支本身不创造新环类别，只是扩大依赖闭包（保守但安全）。

### D3: "布尔表达式"的类型判断采用轻量上下文判定

- 不引入完整类型推理。新增 `semantic::isBooleanExpr(expr)`：
  - 布尔字面量 true/false；`and/or/not`；关系比较（==/<>/</<=/>/>=）；
  - 已声明为 Boolean 类型的标识符；嵌套 if 表达式且分支为布尔；
  - 其他 → 非布尔。条件位置判断非布尔 → MC0204。
- 条件方程 LHS 类型：`der(x)` 必须为状态量；否则必须为已声明变量。
- if 表达式分支类型：数字↔数字允许（隐式提升）；布尔↔布尔允许；其余 → MC0205。

### D4: 代码生成归约

- **if 表达式**（任意表达式位置）→ C++ 三元 `(cond ? a : b)`。
- **条件方程** → semantic 校验通过后，plan 阶段归约为普通等式
  `v = (c1 ? e1 : … : en)`（elseif 链右结合嵌套三元），
  进入既有"表达式求值→赋值"通道。**生成产物与无条件模型保持同构（无 if/else 语句块）**。
- 状态量分支 `if c then der(x)=e1; else der(x)=e2; end if;` → `d.x = c ? e1 : e2`。

### D5: 明确不支持（本版本 VOID）

| 项 | 说明 |
|----|------|
| 多方程/不同未知量分支块 | 需块级依赖分析，见 D1 |
| when / reinit / algorithm / for | 仍停留 kUnsupportedKeywords |
| 事件检测/过零/再初始化 | Clarify Q2 排定 |
| if 内嵌声明或局部作用域 | 无 scope 系统 |
| 若干 if 表达式内嵌方程结构（连接/索引） | 无连接系统 |

## 4. 验证策略

- 单元：新的 AST/parser/semantic 产生式 + 全部非法输入回归（每个新 MC 码至少 1 例）。
- 语义正确性锚点：**分支平衡规则**（MLS 8.3.4）是设计依据，写进 contracts/
  if-construct-contract.md，供 reviewer 与回归比对器核对。
- 金样：新增条件模型（见 quickstart.md）进入 golden 基线；参考基准用参数/常量条件模型
  （omc 与我们会逐点一致），运行期条件模型用集成用例按步边界断言。
- 集成：模型→C++→构建→运行→CSV 断言，切换时刻值验证 D4 归约在真实链路上的正确性。

## 5. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 分支并集依赖过保守导致误判代数环 | D2 注明；用例含"分支各自独立、并集无环"的正例验证不误报 |
| 布尔类型判断遗漏新运算符 | isBooleanExpr 单测覆盖全部运算符 |
| elseif 链深嵌套三元可读性下降 | 限制链深（如 ≥8 级报 MC0205 之外的边界提示）；链少、金样锁定 |
| 条件开关导致输出跳变 vs 参考 | SC-002 容差对运行期条件用例按步边界语义收敛 |

## 6. 结论

方案通过。新增错误码、文法（EBNF delta）、内部数据模型见 Phase 1 产物
（contracts/if-construct-contract.md、data-model.md）；中对应对照表见 plan.md 附录。

**Feature Branch**: `001-modelica-cpp-compiler`

**Created**: 2026-08-24

**Status**: Draft

## Clarifications

### Session 2026-08-24

- Q: 生成的仿真程序应以何种形式输出结果轨迹？ → A: 写入 CSV 结果文件，列为仿真时间与各变量值。
- Q: 验收与回归用的"参考轨迹"从哪里获得？ → A: 由开源仿真工具 OpenModelica 对同一模型运行生成。
- Q: 首期对输入文件中模型的组织方式有什么要求？ → A: 一个文件仅含一个模型，不支持 package 与 import。
- Q: 生成的 C++ 程序运行时是否允许依赖第三方库？ → A: 允许依赖少量开源数学/线性代数库，版本须显式固定并声明。
- Q: 运行生成的仿真程序时，仿真终止时间与输出间隔如何确定？ → A: 由模型内的实验设置注释决定，程序不接受运行参数。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 将 Modelica 模型转换为可运行的 C++ 程序 (Priority: P1)

建模工程师将一份使用受支持子集编写的 Modelica 模型文件交给编译器系统，
系统将其翻译为一套无需任何手工修改即可构建、运行的 C++ 代码；
运行该程序即可复现源模型的仿真行为，并产出关键变量随时间变化的结果轨迹。

**Why this priority**: 端到端翻译是系统的核心价值。没有"合法输入 → 可运行输出"
这条主干，其余能力（验证、诊断）都失去依附对象。

**Independent Test**: 给定一个行为已知的示例模型，独立执行
"转换 → 构建 → 运行 → 检查输出轨迹"四个步骤，全程无需人工修改生成物。

**Acceptance Scenarios**:

1. **Given** 一份仅包含受支持构造的合法 Modelica 文件，**When** 用户发起转换，**Then**
   系统产出一套可直接构建、运行的 C++ 代码，构建与运行零错误。
2. **Given** 同一模型生成的程序，**When** 用户运行它，**Then** 输出的变量轨迹与该模型的
   预期行为在既定容差内一致。
3. **Given** 一个含参数声明的模型，**When** 修改参数值后重新转换并运行，**Then** 输出结果随参数正确变化。

---

### User Story 2 - 翻译正确性的批量回归验证 (Priority: P2)

用户或自动化流程对一组带参考结果的代表性模型批量执行
"转换 → 构建 → 运行 → 与参考结果比对"，系统对每个用例给出明确的通过/失败结论
与量化偏差，用于保证持续迭代中翻译语义不回退。

**Why this priority**: 编译器的价值在于语义等价。项目宪法要求所有功能必须有自动化测试；
本故事把该治理要求落实为产品级的验收与回归手段，是质量底线（优先级仅次于核心主干）。

**Independent Test**: 对一组已知参考结果的用例运行批量验证流程，
得到逐用例的结论报告；人为引入一处翻译缺陷后重跑，受影响用例必须转为失败。

**Acceptance Scenarios**:

1. **Given** 一组附带期望轨迹与容差的模型用例，**When** 执行批量验证，**Then** 每个用例得到
   通过/失败 结论及量化偏差。
2. **Given** 某次改动引入了影响输出的翻译缺陷，**When** 执行批量验证，**Then** 受影响用例被标记为失败，
   未受影响用例保持通过。
3. **Given** 新增一个模型用例及其参考结果，**When** 将其加入验证集，**Then** 无需修改验证流程本身即可纳入执行。

---

### User Story 3 - 非法或不支持输入的清晰诊断 (Priority: P3)

当输入包含语法错误，或使用了超出首期支持范围的 Modelica 构造时，
系统拒绝翻译，以人可读的方式指出问题位置（文件、行号）与原因；
绝不静默产出错误代码。

**Why this priority**: 静默错译比失败更危险，但诊断体验建立在主干可用之后；
因此排在核心翻译与回归验证之后。

**Independent Test**: 提交各类非法样例文件，逐条核对诊断是否包含文件名、行号与原因，
且失败时不产生任何生成物。

**Acceptance Scenarios**:

1. **Given** 含语法错误的 Modelica 文件，**When** 发起转换，**Then** 系统报告含文件名与行号的错误信息，
   以失败状态结束，不产出生成物。
2. **Given** 语法合法但含不受支持构造的文件，**When** 发起转换，**Then** 系统明确指出该构造不受支持
   及其位置，而非给出晦涩或误导性错误。
3. **Given** 多个错误的输入文件，**When** 发起转换，**Then** 系统尽可能一次性报告全部可发现的问题，
   而非每次只报第一个。

---

### Edge Cases

- 空文件或仅含注释的文件：必须给出有意义的诊断（如"未发现可翻译的模型"），不得崩溃或静默成功。
- 方程数量与未知量不匹配（欠定/超定模型）：必须在转换阶段检出并以诊断形式说明。
- 代数环（循环代数依赖）：必须被检出并明确报告，不得产出生成物或死循环。
- 初值导致数值发散的模型：生成程序运行时必须有明确提示，而非无输出挂死。
- 极大模型（数千变量/方程）：转换必须在可接受时间与内存内完成（见 SC-003），超出时给出清晰失败而非崩溃。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 接受 Modelica 源文件作为唯一事实来源的输入，并产出与之对应的 C++ 代码工程。
- **FR-002**: 生成的代码 MUST 在主流标准构建环境下无需任何人工修改即可构建成功；
  允许依赖少量开源数学/线性代数库，但所用第三方依赖 MUST 显式固定版本并随文档声明。
- **FR-003**: 生成的程序运行后 MUST 复现源模型的仿真行为，将关键变量随时间推进的结果轨迹
  写入 CSV 结果文件（列为仿真时间与各变量值），供人工查看与自动化比对直接读取；
  程序 MUST 无需命令行参数即可完成完整仿真——仿真终止时间与输出间隔取自模型内的实验设置注释。
- **FR-004**: 首期 MUST 支持明确界定的 Modelica 子集：模型声明、常量与参数、连续时间微分方程与代数方程、
  初始条件、模型的实验设置注释（仿真终止时间、输出间隔等运行配置）、
  算术/关系/逻辑表达式以及常用初等数学函数；一个输入文件仅包含一个模型；
  package 结构与 import 语句不在首期范围（出现时按 FR-005 拒绝）；子集边界 MUST 随文档发布。
- **FR-005**: 对子集之外的任何构造，系统 MUST 显式拒绝并说明"不受支持"，禁止静默错译或产出不可靠代码。
- **FR-006**: 所有失败情形 MUST 产生包含文件名、行号与原因的诊断信息；成功与失败的退出状态 MUST 可区分，
  以便人与自动化流程同等调用。
- **FR-007**: 相同输入 MUST 每次产生完全相同的转换结果（确定性转换），保障可复现性。
- **FR-008**: 生成代码中的标识符 MUST 与源模型中的名称保持可追溯对应关系，
  使工程师能将运行期问题定位回源模型。
- **FR-009**: 每个受支持的语言构造 MUST 至少由一个自动化测试覆盖其"转换→运行"行为；
  每个已修复缺陷 MUST 附带回归测试用例。
- **FR-010**: 系统 MUST 提供批量"转换→运行→与参考结果比对"的验证方式，
  并对每个用例输出量化偏差与通过/失败结论。

### Key Entities *(include if feature involves data)*

- **Modelica 源模型**: 模型名、声明集合（常量/参数/变量）、初始条件、方程集合；转换的唯一输入。
- **生成产物**: 与源模型一一对应的 C++ 代码集及构建描述；可构建、可运行、标识符可溯源至源模型。
- **诊断消息**: 严重级别、位置（文件/行）、原因描述；面向建模工程师的可读文本。
- **参考用例**: 源模型 + 参数设定 + 期望轨迹（由开源基准工具 OpenModelica 生成）+ 比较容差；驱动验收与回归验证。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ≥20 个覆盖全部受支持构造的代表性模型完成"转换→构建→运行"闭环，
  全程零人工修改生成物，闭环成功率 100%。
- **SC-002**: 全部参考用例的输出轨迹与期望值在既定容差内的一致率达到 100%。
- **SC-003**: 单个典型规模（≤500 行）模型的端到端转换在 10 秒内完成。
- **SC-004**: 100% 的非法或不支持输入被拒绝并返回含位置信息的诊断，零静默错译案例。
- **SC-005**: 建模工程师在不了解编译器内部实现的前提下，依据用户文档能在 15 分钟内
  独立完成首个模型的转换与运行。

## Assumptions

- 首期面向连续时间（ODE 型）模型子集；离散事件、复杂算法控制流、外部函数接口、
  package/import 与多模型文件、Modelica 标准库依赖不在首期范围，留待后续迭代扩展。
- 使用形态为命令行工具——这是编译器领域的标准交互方式，便于人工与自动化流程同等使用。
- "运行生成的程序"指其能从初始条件出发推进仿真时间并输出结果轨迹；
  数值推进的具体方法属于规划阶段的实现决策，本规格不作限定。
- 参考轨迹由同一模型在开源仿真工具 OpenModelica 中的运行结果生成；
  该工具可脚本化调用，以支撑批量回归验证。
- 首期不做物理单位检查与换算；涉及单位语义的场景按超出范围处理（显式拒绝）。
